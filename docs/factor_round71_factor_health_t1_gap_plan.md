# Round 71 `factor_health` 的"月末缺 T+1"显式提示（成因可见化）· 预注册 + §0

> 状态：**已预注册并实施 2026-10-09**
> 触发：R65 §0 曾记录"RankIC 序列末期为 2026-07-31，比数据末尾 09-30 落后两个月"。
> 代码：`scripts/r5/factor_health.py`

## 1. 结论：**不是 bug**

`factor_health` 的构造：

```python
sig_days = [t for t in month_last_days(idx) if idx.get_loc(t) + 1 < len(idx)]  # 需存在 T+1
if k + 1 >= len(sig_days):
    continue                                                                   # 末期无未来收益
```

两次"排除"叠加：

1. RankIC 需要**下一月末**的未来收益 → 最后一期必然被跳过（固有，正确）；
2. `sig_days` 还要求该月末**存在次一交易日作为执行日** → 当数据**恰好止于月末**时，
   该月末被排除 → 连"倒数第二期"也没了 → 窗口**静默**少一期。

**实测闭环**：数据止于 09-30 时 RankIC = 140 期（末期 07-31）；
补上 10-08 后重跑 → **141 期（末期 08-31）**，自动追上，**无需改任何计算**。

## 2. 预注册规则与判据

新增纯函数 `_t1_gap_note(idx, sig_days) -> str | None`，在"数据止于**该月最后一个工作日**"时
打印一行显式提示；否则不打印。判据：

| 判据 | 标准 | 结果 |
|---|---|---|
| **Q1 情形出现即提示** | 数据止于 2026-09-30（真月末）→ 给出提示，含"不是数据缺失" | ✅ |
| **Q2 正常情形不提示** | 数据止于 2026-10-08（非月末）→ 无提示 | ✅（首版误报，已修） |
| **Q3 判别力自证** | 旧版在同一情形**必然静默**；新版必须给出提示 | ✅ |
| **Q4 质量门** | ruff 0 + pytest 全过 | ✅ |

**实施中发现并修正的自身缺陷**：首版用 `month_last_days(idx)[-1]` 判断"月末"，
而该函数会把**指数最后一天**当成月末 → 10-08 被误报为"月末缺 T+1"。
改为判断"是否真的是该月最后一个工作日"（`pd.bdate_range(月初, 月末)[-1] == idx[-1]`）后 Q2 通过。

## 3. 诚实风险

- 该提示只做**可见化**，不改变任何计算；RankIC 的"末期必然落后一期"是设计固有；
- 提示基于工作日日历（非交易日历），节假日错位时可能不触发 —— 影响仅限于少一句提示。
