## 2. 规则（定死）

1. **只读**：不得写任何文件（含创建/改 mtime）；
2. **配置化**：账户列表/输出目录取 `cfg.r5/p3.*`，不硬编码账户标签；
3. **复用不重复**：对账直接 import `scripts.recon_ops`（`run_strategy`），不复制不变量逻辑；
4. **节假日表内置**：2026 年 **17 个**休市工作日（已与本地面板逐一核对：
   春节 02-16~02-20 + 02-23、清明 04-06、劳动节 05-01/05-04/05-05、
   端午 06-19、中秋 09-25、国庆 10-01/10-02/10-05/10-06/10-07）；
5. **`--probe` 消除不确定性**：对"不在节假日表里的缺失工作日"，可选地查数据源
   （`fetch_daily_incremental.probe_dates`，一次登录）来**判定是节假日还是真缺口**；
6. argparse：`--strat {all,r5,p3}` / `--days N` / `--probe` / `--verbose` / `--config`；
   退出码 `0`=通过、`1`=有异常。

## 4. 诚实风险

1. **节假日表存在"自证"局限**：该表是从本地面板反推 + 对照节日名核实的，
   因此**对已覆盖的历史时段无鉴别力**（数据少一天，表里也就少一天）；
   它真正的用途是**抓新增缺口**（如 10-12 那种漏拉）—— 这一点在脚本 docstring 里写明；
2. **节假日表只覆盖 2026**：`--days` 跨到往年时，往年缺失工作日会以 ⚠️ 列出（不算失败），
   需 `--probe` 或补表才能定性；
3. **`--probe` 需要网络**（1 次登录 + 每日 5 只探测），默认关闭。
