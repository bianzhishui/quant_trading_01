## 1. 已知事实（实测）

两个版本都在 git 里，可精确对比：

| 版本 | commit | 日期 | 行数 / code 数 |
|---|---|---|---|
| 旧（建账时使用） | `f69eef5` | 2026-09-05 | 3193 / 3193 |
| 新（当前工作区） | `a8c5adc` | 2026-09-22 | **3484** / 3484 |

**对比结果（决定性）**：

- 共同 code **3193 个，行业标签 100% 相同，无一变更**；
- 新版**仅新增 291 个 code**（无删除）；
- 旧 81 个行业 → 新 82 个行业。

→ 因此影响**不是**"标签重排"，而是**池成员扩容**。路径有三条：

1. `_load()` 里 `ind.reindex(close.columns).dropna()` → 无行业标签的 code 一律被**排除出池**；
2. `r5_rebalances` 的 `common = amihud ∩ mom ∩ f4 ∩ ind` → 同上；
3. `keep = ind 行业内成员数 ≥ min_ind(5)` → 新增成员可能**救活**此前因不足 5 只而被剔除的行业
   → 该行业股票整体进入池（这条最可能是基准平移 5.6% 的主因）。

新增的 291 只以**退市股**为主（`raw_close_delisted.parquet`、R17 退市股宇宙同期建设），
其历史收益通常较差 → 会**拉低**同池等权基准。与实测方向一致：
新基准 `bench_lv[09-01]` **2.4908 < 旧 2.6313**（下跌更多）。

## 2. 规则（定死）

**同一 close/amount/tst/isst 面板，只替换 `ind`（行业映射）**，其余口径全部不动：

- 面板：`scripts.r5.paper_live._load()` 得到 close/amount/tst/isst（一次加载，两臂复用）；
- 指标：`r5_rebalances(...)` → `ew_nav(ret, sets, 15e-4)` vs `ew_nav(ret, bench, 15e-4)`；
- 分段：全区间 / 训练 2014-2021 / 验证 2022-2026（R38/R59 同口径）；
- 旧表来源：`git show f69eef5:data/round2/industry_full.parquet` → `tmp/industry_full_0905.parquet`；
- **不写入任何数据文件、不改生产代码**；只读分析。

## 4. 诚实风险

1. **只测一个维度**：本轮量化 `ind` 的影响；**不排除**同时期还有其它数据变更
   （如 `full_daily` 年分区被 `write_full_daily` 重写）也贡献了部分平移。K1 若精确命中
   2.631265 则可排除其它因素；若只是接近，则须如实标注"行业表为主因，非唯一"。
2. **不重发历史数字**：本轮只产出"影响面 + 是否需标注"的判断，是否重跑/重发由用户决定。
3. **两个版本之间的 291 只新增 code 无法逐只溯源**（无中间快照），只能整体量化。
